# My Mail 产品需求文档（PRD）

版本：v0.1 历史草案｜日期：2026-11-07｜最近同步：2026-11-08（0.1.9 收口，见 §11）

> 这份文档保留早期产品设想，不代表当前发行版承诺。支持的平台、已实现功能与限制以 [README](../README.zh-CN.md) 为准，后续方向见[路线图](ROADMAP.md)。下文中的内存、体积、工期与兼容性数字是当时的目标，不是当前的实测结论。

## 1. 背景与目标

### 1.1 背景

主流邮箱客户端要么体积大、占用高（Electron 系），要么功能臃肿，要么只绑定单一服务商。MyGo 是 Go + 系统 WebView 的桌面应用框架，产物是几 MB 的单一二进制，内存和 CPU 占用低，且纯 Go、无 cgo，可在任意机器交叉编译全平台。这与「轻量、快、跨平台」的邮件客户端诉求高度契合。

### 1.2 产品定位

一款轻量、快速、隐私友好的跨平台桌面邮箱客户端，通过标准 IMAP/SMTP 协议支持 Gmail、QQ、163、Outlook 等绝大多数邮箱服务。

### 1.3 目标

- 用 10 天左右完成可日常使用的 MVP，覆盖收、读、写、管理四类核心场景。
- 安装包小于 20 MB，空闲内存占用低于 150 MB。
- 邮件数据与凭证只存在本机，不经过任何第三方服务器。

### 1.4 非目标（MVP 不做）

OAuth2 登录、全文索引、虚拟滚动、PGP/S/MIME、规则与过滤器、日历与联系人同步、移动端。IMAP IDLE 实时推送与多账号合并视图原列在此，已在 0.1.9 提前实现（见 §11）。

## 2. 目标用户与场景

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| 个人用户 | 有 1–2 个邮箱，日常收发 | 打开快、界面干净、不卡 |
| 开发者/极客 | 在意资源占用和隐私 | 轻量、本地存储、无追踪 |
| 国内邮箱用户 | 使用 QQ/163 等 | 中文编码无乱码、授权码登录顺畅 |

典型场景：

1. 早上打开应用，查看新邮件并快速回复。
2. 阅读带附件的邮件并保存附件。
3. 在网页等处点击 mailto 链接，直接弹出写信窗口。
4. 离线时回看已同步过的邮件。

## 4. 功能需求

### 4.1 账号管理（P0）

- 支持输入邮箱、IMAP/SMTP 服务器、端口、加密方式（SSL/TLS、STARTTLS）和授权码。
- 内置常见邮箱服务商预设（Gmail、Outlook、QQ、163、126），选中后自动填充服务器参数。
- 保存前进行连接测试，失败时给出可读的错误原因（认证失败、网络不通、证书异常）。
- 密码/授权码仅存入系统钥匙串，不写入配置文件或数据库。
- 提示用户：多数邮箱需先在网页端开启 IMAP 并生成授权码。

### 4.2 文件夹与邮件列表（P0）

- 左栏显示文件夹（收件箱、已发送、草稿、垃圾箱、已删除及自定义文件夹）与未读数。
- 邮件列表显示发件人、主题、摘要、时间、未读标记、星标、附件图标。
- 按时间倒序，分页加载（每页 50 封），使用虚拟滚动。

### 4.3 阅读邮件（P0）

- 点开邮件时才拉取正文与附件，拉取后缓存本地。
- 支持 HTML 与纯文本，HTML 邮件须经安全处理（见 6.2）。
- 正确处理 UTF-8、GBK、GB2312、Base64、Quoted-Printable 等编码。
- 显示附件列表（文件名、大小），点击后通过系统保存对话框下载。
- 打开邮件后自动标记为已读（可在设置中关闭）。

### 4.4 写信（P0）

- 新建邮件：收件人、抄送、密送、主题、正文、附件。
- 回复、回复全部、转发，自动带入引用内容与「Re:/Fwd:」前缀。
- 正文 MVP 阶段支持纯文本；发送时同时生成 text/plain 与 text/html 两部分。
- 发送成功后自动保存一份到「已发送」；发送失败给出提示并保留草稿内容。
- 收件人格式校验。

### 4.5 邮件管理（P0）

- 删除（移入已删除；在已删除中再次删除为永久删除，需二次确认）。
- 标记已读/未读、加星标。
- 移动到指定文件夹。
- 所有操作先更新本地，再异步回写服务器；回写失败时回滚本地状态并提示。

### 4.6 搜索（P1）

- 在当前账号已缓存的邮件中，按发件人、收件人、主题关键字搜索。
- 搜索结果与列表复用同一展示组件。

### 4.7 桌面集成（P1）

- 新邮件到达时发送系统通知，点击通知定位到该邮件。
- 托盘/菜单栏图标显示未读数。
- 注册 mailto: 协议，点击链接打开预填收件人的写信窗口。
- 单实例运行：重复启动时唤起已有窗口，避免多个进程同步同一账号。
- 记忆窗口大小与位置。

### 4.8 草稿（P1）

- 写信窗口每 30 秒自动保存草稿到本地，关闭时询问是否保留。
- 草稿 MVP 阶段仅本地保存，不同步到服务器草稿箱。

### 4.9 设置（P1）

- 同步间隔（默认 60 秒）、是否自动标记已读、是否默认加载远程图片（可信发件人默认加载，其他发件人默认阻止）、通知开关、深浅色主题。

## 5. 非功能需求

| 类别 | 指标 |
| --- | --- |
| 性能 | 冷启动到可操作小于 2 秒；打开已缓存邮件小于 200 毫秒；列表滚动不掉帧 |
| 资源 | 安装包小于 20 MB；空闲内存小于 150 MB |
| 平台 | macOS 12+、Windows 10+、主流 Linux 发行版（x64 与 arm64） |
| 可靠性 | 网络断开后自动重连；所有 IMAP/SMTP 操作带超时；崩溃不丢失草稿 |
| 隐私 | 凭证存系统钥匙串；本地数据不上传；日志不记录邮件内容与密码 |
| 可维护性 | 邮件核心逻辑与界面解耦，便于后续替换前端 |

## 6. 技术方案概要

### 6.1 架构

- **前端：** TypeScript + Web 框架（React/Vue/Svelte，待定），运行在系统 WebView。
- **后端：** Go，通过 MyGo 的类型化 IPC 绑定服务，TS 客户端由 Go 代码自动生成；同步进度、新邮件等通过事件或 channel 推送。
- **服务划分：** AccountService、MailService、ComposeService、SettingsService。
- **协议库：** go-imap v2、go-message、go-smtp（或标准库 net/smtp）。
- **存储：** SQLite（modernc.org/sqlite，纯 Go）；凭证使用系统钥匙串（go-keyring）。

### 6.2 HTML 邮件安全

- HTML 放入 sandbox 的 iframe，禁用脚本。
- 渲染前使用 DOMPurify 等进行清洗。
- 默认屏蔽不可信发件人的远程图片以防追踪像素；可信发件人自动加载，并提供「加载一次」「信任发件人」「总是阻止」操作。
- 链接点击交由系统浏览器打开，不在应用内跳转。

### 6.3 同步策略

1. 首次进入文件夹：拉取最近 50 封邮件头并缓存。
2. 点开邮件时懒加载正文与附件。
3. 再次进入文件夹：校验 UIDVALIDITY，仅拉取 lastUID+1 之后的新邮件；UIDVALIDITY 变化则清空该文件夹缓存并重新同步。
4. 每 60 秒轮询一次，并支持手动刷新。
5. 本地操作先改本地，再异步回写服务器。

### 6.4 核心数据模型

| 实体 | 关键字段 |
| --- | --- |
| Account | id、邮箱地址、显示名、IMAP/SMTP 主机与端口、加密方式（密码在钥匙串） |
| Folder | id、account\_id、名称、特殊用途标识、UIDVALIDITY、最后同步 UID、未读数 |
| Message | id、account\_id、folder、UID、发件人、收件人、主题、日期、已读、星标、摘要、正文（懒加载）、是否有附件 |
| Attachment | id、message\_id、文件名、大小、MIME 类型 |
| Draft | id、account\_id、收件人、抄送、密送、主题、正文、附件路径、更新时间 |

## 7. 关键流程

**添加账号：** 选择服务商预设 → 填写邮箱与授权码 → 测试 IMAP 与 SMTP 连接 → 成功后写入钥匙串与数据库 → 首次同步文件夹。

**阅读邮件：** 点击列表项 → 本地有正文则直接渲染，否则向服务器拉取 → 写入缓存 → 渲染并标记已读 → 异步回写已读标记。

**发送邮件：** 填写并校验 → 通过 SMTP 发送 → 成功则存入已发送并清除草稿；失败则保留草稿并提示原因。

## 8. 里程碑

| 阶段 | 周期 | 交付 |
| --- | --- | --- |
| M1 | 第 1–2 天 | 脚手架跑通；添加账号、钥匙串；列出文件夹与邮件头 |
| M2 | 第 3–4 天 | 正文解析与中文编码；SQLite 缓存；三栏界面与阅读 |

## 9. 成功指标

- 功能：P0 用户故事全部通过验收。
- 性能：满足第 5 节的启动、内存、包体积指标。
- 兼容：Gmail、QQ、163、Outlook 四个邮箱完成收发全流程验证，中文邮件无乱码。
- 稳定：连续运行 8 小时无崩溃、无明显内存增长。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| MyGo 为 v0.1，API 可能变动或存在缺陷 | 进度与稳定性 | 邮件核心逻辑与 MyGo 解耦；开发前通读其 docs；锁定版本 |
| 各邮箱服务商 IMAP 行为不一致 | 同步异常 | 先覆盖四家主流邮箱，建立兼容性测试清单 |
| Gmail、Outlook 逐步限制密码登录 | 无法添加账号 | MVP 明确提示限制；v2 引入 OAuth2 |
| HTML 邮件带来安全与渲染问题 | 隐私泄露、显示错乱 | 沙箱 + 清洗 + 默认屏蔽远程内容 |
| 系统 WebView 版本差异（尤其 Linux WebKitGTK） | 界面表现不一致 | 前端避免过新特性，三平台各做一轮手测 |
| 邮件量大时首次同步慢 | 体验差 | 仅同步最近邮件头，按需拉正文，分页加载 |

## 11. 后续版本规划

- **v1.1：** OAuth2（Gmail/Outlook）、邮件规则与过滤的后续扩展、自动更新。
- **v1.2：** 全文搜索索引、草稿同步到服务器。
- **v2.0：** PGP/S/MIME、联系人与日历、插件机制（MyGo 已有插件能力）。

### 状态校正（0.3.0 收口时）

- **已提前交付**：IMAP IDLE 实时推送、多账号统一收件箱（原列 v1.1），以及草稿防丢与重开恢复（原列 P1，现上调为 P0）。
- **已交付（0.2.0）**：邮件管理四件套与持久化待同步队列（4.5）、发送附件与密送、按服务商配置的「已发送」APPEND（4.4）、偏好设置四项（4.9）、按信件分槽的草稿（4.8）。
- **已交付（0.3.0）**：mailto 深链（4.7）、虚拟滚动（4.2）、本机缓存容量上限与淘汰（4.6 / 验收文档第 3 条）。P0 用户故事至此全部覆盖。
- **仍缺（产品化 / 平台化）**：真实 QQ / 163 账号端到端验收、OAuth2（Gmail / Outlook）、全文索引（原 v1.2）、草稿同步到服务器、Windows / Linux 与旧版 WebView 兼容、自动更新、完整进程组内存与 8 小时稳定性验收。
- **首轮兼容验收**：Outlook.com 的 IMAP 需要 OAuth2，与「MVP 不做 OAuth2」冲突；建议首轮只验收 QQ / 163，Outlook 与 Gmail 放到 OAuth2 之后。
- **推荐顺序**：先做真实账号端到端验收，再做平台兼容与资源 / 8 小时稳定性，最后排 OAuth2、全文索引与自动更新。
