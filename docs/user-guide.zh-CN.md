# 使用指南与实现说明

基于 grweb 的 React 桌面邮箱原型。Go 负责 IMAP / SMTP、MIME 解析、SQLite 与系统凭证存储；界面通过 MyGo 自动生成的 TypeScript 客户端调用服务。

当前公开预览版本 **0.0.1**（2026-11-08）：变更明细见 [CHANGELOG.md](../CHANGELOG.md)，原型尚未覆盖的部分与下一阶段顺序见文末「当前范围」及 PRD §11。

## 启动

需要 Go（版本见根目录 go.mod）、Bun（版本见 .bun-version），以及操作系统 WebView。本次验证环境为 macOS arm64。

```sh
bun install --frozen-lockfile
bun run dev
```

`bun run dev` 启动桌面程序与 Vite。`bun run dev:web` 仅提供界面开发服务，普通浏览器没有 MyGo IPC，不能独立完成邮件操作。

```sh
bun run generate   # 更新 src/mygo.ts；不要手改生成文件
bun run test       # Go 存储、MIME、TLS 协议测试与 HTML 安全测试
bun run build      # 构建桌面应用与安装包
```

macOS 构建位于 `build/darwin-arm64/My Mail.app`，可直接打开。安装包为同目录的 `.dmg`。

## 验证闭环

1. 打开应用，点击“打开本地示例”。这一步通过 IPC 调用 Go，向 SQLite 写入明确标注的示例账号与邮件。
2. 点击示例邮件，查看 HTML 排版渲染。示例发件人不在可信范围，脚本和远程图片在渲染时会被移除。
3. 退出并重新启动应用，示例邮件仍可离线读取。
4. 在“账号设置”添加真实邮箱。QQ、163 需先在服务商网页开启 IMAP 并生成授权码；Gmail 需要账号允许生成应用密码。Outlook OAuth2 尚未实现。
5. 设置 IMAP 与 SMTP 服务器，点击“测试连接并保存”。仅在两项加密认证均通过后保存账号；授权码保存在系统凭证库，数据库仅包含服务器配置。
6. 点击“刷新邮件”，获取当前文件夹最近 50 封邮件头。继续向下滚动列表会按每页 50 封自动加载更早的邮件；点击邮件后按需读取正文，已加载的邮件头与正文可离线阅读。
7. 阅读邮件时可点“回复”“回复全部”或“转发”，自动带入收件人、主题前缀与原邮件纯文本引用（回复全部把原发件人放在收件人、其余参与者在抄送）；“写邮件”永远从空白新邮件开始，不会带入上一封的收件人与引用（本机若存着一份未发送的草稿，会在窗口顶部提示“继续编辑”）。收件人与抄送用 chip 展示，输入地址后按回车 / 逗号即成为一条，退格删除最后一条。支持 ⌘/Ctrl + Enter 发送，正文 Enter 只换行。编辑时自动保存本地草稿（每敲一次键就落盘，正文里的引用一并保存）；“保存并关闭”会等待保存完成，没有改动过就关闭则不会写入草稿。写了一半的回复不小心关掉（或退出应用）后重新点“回复”，会连同收件人、抄送、主题与原文引用一起恢复，顶部状态显示“已恢复上次未写完的内容”；只认主题相同、且引用里的原邮件日期与发件人也对得上的那一份草稿，其他草稿不会被混进来，只在窗口顶部提示“继续编辑”。
8. 仅在确认收件人和内容后手动发送。服务不会自动重试发送结果不明确的邮件，避免重复发送。

请直接在应用里输入授权码，不要将凭证写进源码、配置或聊天记录。

## 当前范围

- 账号添加、IMAP / SMTP 的 TLS 与 STARTTLS 认证、系统凭证存储。
- 文件夹列表、按设置间隔（默认 60 秒，可在 15–600 秒间调整）自动检查收件箱及手动同步最近 50 封邮件头、正文懒加载、本地阅读与列表搜索。
- 邮件列表滚动到底部时按 UID 向前分页，每页 50 封自动加载更早邮件；也可点击“加载更早邮件”，失败时可单独重试。已加载的历史页保留在本地缓存。
- 同步时检查 UIDVALIDITY，并核对当前 50 封窗口内的存在性与标记；更早的历史页不受最近窗口清理影响。
- HTML 使用 DOMPurify 白名单、不透明源 sandbox iframe 与 CSP（只允许应用注入的 nonce 桥接脚本，邮件自身的脚本仍被移除）。来自本机账号域名或常见邮箱服务商（如 QQ、Gmail、Outlook、163，含 `vip.163.com` 这类子域）的发件人默认视为可信：自动加载远程图片与邮件内链接，并保留邮件自带的 `<style>`、`style`、`class` 与表格布局属性，只过滤 `position` / `z-index`、`@import`、`expression()` 等版面逃逸或外链写法。仿冒域名（如 `qq.com.evil.test`）不算可信。其他发件人默认阻止：图片需手动“加载图片”，且按统一的安全排版显示，不带邮件自带样式；也可持久化“信任域名 / 总是阻止”：信任按可注册域名生效（信任 `status-cn-01.flashduty.com` 会覆盖同域的 `status-cn-03`，`mail.sina.com.cn` 与 `news.sina.com.cn` 同属 `sina.com.cn`），阻止仍只针对具体地址；旧版本按地址保存的信任记录会在读取时折算成域名。邮件内链接不再单独列出，点击正文里的链接即视为授权打开。邮件脚本、外部 CSS 与非 HTTP(S) 资源始终阻止。正文锚点只保留 `data-mail-href`（不保留 `href`，框架无法跳转），点击或回车后由文档内唯一一段带 nonce 的脚本经 `postMessage` 回传页面，校验来源与 `safeHttpLink` 后交系统浏览器打开；框架为不透明源（`sandbox="allow-scripts"`，不含 `allow-same-origin`），读不到应用的 DOM、存储与 Cookie。
- 纯文本写信，同时生成 text/plain 和转义后的 text/html；收件人、抄送、密送各自独立，抄送进入 `Cc` 头、密送只进 SMTP 信封（不写邮件头），所有收件人在信封里去重后投递一次，地址里的换行会在发出前被拒绝；附件通过系统多选面板添加，发送时由 Go 读取本机文件并以 `multipart/mixed` 编码（单个 ≤10 MB、合计 ≤25 MB）。本地草稿按信件分槽自动保存（含抄送、密送与附件路径）；发送成功后保存本地原始邮件记录，可选在确认投递后追加到服务器「已发送」。发件人显示在弹窗底部、发送按钮左侧。
- 阅读视图顶部工具条固定不动：回复、回复全部、转发，以及星标、已读/未读切换、移动到文件夹（先选择目标，再点“移动”）、删除（确认弹窗；已删除文件夹内二次删除为永久删除）。这些操作先改本机缓存、再异步回写 IMAP，未同步的操作持久化在 `pending_ops`，重启或断网后自动重放；永久失败会回滚本地状态并提示。
- 阅读视图工具条固定、主题/发件人/正文整体滚动；正文 iframe 由文档内脚本上报高度撑满，不产生内嵌滚动条（正文用 `padding` 而非 `margin`，过宽的固定宽表格会按比例 `zoom` 缩放以消除横向滚动条）。
- 写信窗口把原邮件放进独立引用卡片：显示原发件人、时间、收件人与主题，HTML 正文按与阅读区相同的清洗规则渲染（远程图片不加载），可折叠。发送时仍以纯文本引用附在正文下方——回复每行加 `> ` 前缀，转发保留分隔线与邮件信息；草稿重开后按纯文本还原引用卡片。
- 附件在正文下方逐行列出文件名与大小，点击“保存”由系统保存面板选择位置（默认 `~/Downloads`）。字节随正文一起缓存在本机 SQLite（`attachments` 表），因此断网也能保存；文件名会去掉路径分隔符、控制字符与前导点，不会写出选定目录之外。内嵌图片（`Content-Disposition: inline`）不算附件，也不会出现在列表里。整封邮件上限 8 MB，超出时提示改用网页邮箱下载。
- 单实例运行、窗口位置记忆、深浅主题、菜单栏图标（与 App 图标同一套 M 字形模板图）与未读数量、新邮件系统通知。
- 窗口隐藏原生标题栏：不显示应用名与图标，页面占满窗口并自绘可拖拽顶栏，仅保留下移的窗口按钮（页面用 `--mygo-titlebar-height` 留出空间）。
- 邮件列表虚拟滚动：固定行高 + 上下占位，只挂载视口附近的行；滚动到底仍按每页 50 封加载更早邮件，DOM 行数不随缓存增长。
- `mailto` 深链：注册为系统邮件链接处理器（macOS 需在「默认邮件阅读器」里选 My Mail），冷启动、运行中点击与第二实例传参都会打开预填收件人 / 抄送 / 密送 / 主题 / 正文的写信窗口；设置页可点「测试写信窗口」直接验证。链接在 Go 侧解析并过滤头注入与控制字符，不会覆盖本机已有草稿。
- 本机缓存上限：设置里按每个账号的每个文件夹保留最新 500 / 2000 / 5000 封（或不限制），超出时连正文与附件一起淘汰；等待同步到服务器的操作不会被清理。设置页显示占用并提供「立即清理」。

这是一轮技术可行性原型，PRD 的 P0 用户故事已基本覆盖，阶段 3 的 mailto 深链、虚拟滚动与缓存容量上限也已落地，剩余的是规范化与平台化工作：阅读区只保留排版视图，没有纯文本切换（仅当邮件没有 HTML 正文时才退回纯文本显示）。回复与转发的引用卡片按原文渲染但发送内容仍是纯文本；远程图片的可信判断基于发件人地址与域名，未校验 SPF / DKIM / DMARC；附件可以收发但暂不预览 PDF/图片；OAuth2（Gmail / Outlook）、全文索引、草稿同步到服务器、Windows / Linux 兼容、自动更新与 8 小时稳定性验收仍未完成。设置右下角“完成”关闭窗口，偏好修改即时生效。设置页提供检查间隔、自动标已读、远程图片默认策略、服务器已发送副本、缓存上限与通知开关。

发送成功后默认不执行 IMAP APPEND：部分服务商会自动保存副本，直接追加可能重复；需要时可在设置里开启「发送后把副本追加到服务器已发送」。本地原始发送记录位于 `sent` 表，尚无展示页。

## 连接排查与日志

添加账号时，界面依次显示 IMAP 测试、SMTP 测试、系统钥匙串保存三个阶段。每项网络测试最多 15 秒，取消/超时会关闭底层连接；界面另设 18 秒等待兜底。测试失败会显示本次测试编号，可按编号查日志。只有两项测试均成功后才保存凭证；系统钥匙串可能弹出解锁提示，此阶段会单独提示。

账号设置底部显示诊断日志路径。macOS 正式版默认为 `~/Library/Application Support/My Mail/logs/app.jsonl`，开发版位于 `My Mail Dev/logs/app.jsonl`。日志采用 JSON Lines，记录连接协议、服务器/端口、加密方式、TCP / TLS / STARTTLS / 欢迎消息 / 认证阶段、结果、耗时、测试编号，以及凭证存储和本地数据库保存阶段。同步、阅读和发送还记录操作编号与耗时。

日志不记录密码、授权码、邮箱地址、邮件内容、IPC 参数或服务器原始响应。日志权限为当前用户可读写，单文件约 2 MB 自动轮转，保留 3 份历史文件。`MYMAIL_LOG_LEVEL=debug bun run dev` 可调整日志级别；连接排查所需信息默认 INFO 级别即可查看。

0.1.1 修复了 QQ / 腾讯企业邮箱的 IMAP 命令顺序问题：先等待服务器欢迎消息，再发送 LOGIN。已用延迟欢迎消息的本地服务器回归验证，并用两家线上服务器的空凭证诊断请求验证能及时收到拒绝回复；这不代表真实账号认证已通过。

## 文件夹导航

系统文件夹依次为收件箱、已发送、草稿、星标邮件、归档、所有邮件、垃圾邮件、已删除，仅显示服务器实际提供的项目。优先使用服务器 SPECIAL-USE 标识，缺失时兼容常见中英文名称。其他目录放在“我的文件夹”，按服务器真实分隔符建立层级，同级按名称自然排序。

箭头控制展开收起，文件夹名称控制打开；不可选的父目录点击名称也可展开。展开状态按账号保存为界面偏好；切换到子文件夹时会显示其父目录。可在父目录名称上使用左右方向键展开或收起。侧栏不将最近 50 封缓存数量当作未读数量显示。

## 菜单栏与新邮件通知

macOS 菜单栏显示邮箱图标和所有账号收件箱的未读总数（0 时只显示图标），Dock 同步显示角标。其他平台在支持的托盘环境中显示图标与数量提示。未读数来自服务器 STATUS，覆盖整个收件箱，并非最近 50 封缓存的计数；不把归档、垃圾箱等文件夹重复计入。

默认每 60 秒检查一次真实账号的收件箱（间隔可在设置里改成 15–600 秒），并更新最近邮件头和已读标记。首次检查只建立基线；之后仅对新增 UID 中尚未读的邮件发通知，旧邮件改回未读不会重复通知。检查点跨重启保留，UIDVALIDITY 变化时重新建立基线。检查失败会保留最后一次成功的计数，并在菜单栏悬停提示和账号设置中说明部分账号未更新。

通知不靠轮询等：每个真实账号额外保持一条 IMAP IDLE 长连接（沿用同一套登录与 TLS 校验），服务器一收到新邮件就推 `EXISTS`，应用立刻走一次常规检查并弹通知，因此延迟从“最多 60 秒”降到一两秒。IDLE 每 24 分钟重发一次（RFC 2177 要求低于服务器的 30 分钟上限），断线、睡眠唤醒或换网后指数退避重连（5 秒起，5 分钟封顶）；服务器不提供 IDLE 时自动退回轮询，不会反复重试。轮询仍然保留，用来纠正未读数、处理 UIDVALIDITY 变化和兜住不支持 IDLE 的服务器。检查做完判定就发通知，不等最近 50 封的同步完成；正在跑别的检查时会等它结束后立刻补一次。macOS 的专注模式或通知权限被关掉时，通知仍可能被系统延后或不显示，这与应用无关。

点击菜单栏图标可打开菜单，选择打开邮箱、立即检查、新邮件通知或退出。关闭窗口会隐藏窗口并继续后台检查；使用菜单中的“退出 My Mail”或系统退出命令结束程序。通知点击会唤起应用，并按账号、UID 和 UIDVALIDITY 定位邮件；邮件被移除时显示提示。

在“账号设置”中可切换新邮件通知，并发送测试通知。macOS 首次发送通知时需要系统授权；如被拒绝，界面会提示前往系统设置开启。系统通知仅显示新邮件数量，不展示主题、发件人或正文。

打开正文成功后会尝试将邮件标为已读（可在设置里关闭）；标记已读、星标、移动与删除都先改本机缓存，再由 `pending_ops` 持久化的离线队列异步回写 IMAP，重启或断网后自动重放，永久失败才回滚并提示。

## 邮箱切换与所有收件箱

侧栏提供可收起的“所有收件箱”分组，下面可单独打开各账号收件箱；通过账号设置添加邮箱。上次选择的账号/汇总视图和分组展开状态会保留。

“所有收件箱”汇总所有已添加账号的已缓存收件箱邮件，按实际邮件时间倒序排列，并标记来源邮箱。刷新会检查全部真实账号；打开邮件、标记已读均使用该邮件所属账号。查看汇总邮件时，新建写信默认使用当前邮件的来源账号，写信窗口中会明确显示发件人。

汇总视图不会混入已发送、草稿或垃圾箱。打开时仅展示各账号已缓存的收件箱邮件；滚动到底部会分别向各账号加载更早邮件并合并排序，未加载的历史不会预先下载。

## 标志与应用图标

标志是一个字母 M：两条竖边加一道深 V，深 V 同时是信封翻盖，所以单字母也读作“信”。配色取自界面 token（`--accent`、`--text`、`--bg`）。

源文件在 `design/logo/`（`logo.svg`、`logo-mono.svg`、`logo-dark.svg`、`logo-mark.svg` 与各尺寸 PNG，`brand-sheet.png` 是展示页），说明见 [标志说明](../design/logo/README.md)。应用图标由 `resources/icon.png`（1024×1024，带 alpha）经 `mygo.config.ts` 的 `icon` 字段打进 `AppIcon.icns`。

## 签名与钥匙串弹窗

`mygo build` 默认用 ad-hoc 签名（`-`），指定要求就是本次构建的 cdhash，所以**每次重新打包都是一个“新应用”**：macOS 会重新询问“My Mail 想要使用钥匙串中的 dev.mymail.desktop 的机密信息”。

`mygo.config.ts` 现在会自动挑选本机一个稳定的签名身份（优先 `Developer ID Application`，其次 `Apple Development`），拿不到就回落到 ad-hoc：

```sh
security find-identity -v -p codesigning   # 看看有哪些身份
MYMAIL_SIGN="Apple Development: …" bun run build   # 指定别的身份
MYMAIL_SIGN="-" bun run build                     # 强制回到 ad-hoc
```

签名后指定要求变成 `identifier "dev.mymail.desktop" and certificate leaf = H"…"`，与构建内容无关。**改成稳定签名后还会再问最后一次**（旧的钥匙串条目记的是旧身份），点“始终允许”即可；此后重新打包、覆盖安装都不会再弹。

注意：这是本机开发签名的便利，不等于分发。对外发布仍需 Developer ID + 公证（notarization），否则别人的 Mac 上会被 Gatekeeper 拦下。
