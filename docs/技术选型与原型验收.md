# 技术选型与原型验收

日期：2026-11-07。依据 PRD v0.1 与用户指定的本地 grweb 基础项目。

> 本文是原型阶段的验证记录。当前功能与支持范围见 [README](../README.zh-CN.md)，后续方向见[路线图](ROADMAP.md)；历史包体、测试次数和开发机观察不作为当前发行版的性能或服务商兼容承诺。

## 已落地选择

| 层 | 选择 | 说明 |
| --- | --- | --- |
| 桌面 | MyGo v0.6.3 | 锁定版本；系统 WebView；类型化 IPC |
| 前端 | React 19 + TypeScript + Vite | 继承 grweb 的技术栈与基础控件 |
| 样式 | Tailwind 4 + Gr8r token | 控件高度、字体、圆角遵循原有规范 |
| 组件 | Radix Dialog / Slot + 原有 Button / Input 等 | 仅迁入当前需要的组件，未引入演示业务与 TipTap |
| IMAP | go-imap/v2 v2.0.0-beta.8 | 封装在 Go 服务内部；预发布依赖须锁版本 |
| SMTP | go-smtp v0.25.1 + go-sasl | 替代冻结功能的 net/smtp |
| MIME | go-message v0.18.2 + charset | 收信解码与 multipart/alternative 写信 |
| 数据 | modernc.org/sqlite v1.61.1 + database/sql | 无 cgo；SQLite WAL；当前单连接 |
| 凭证 | mygo.Secrets | 使用系统凭证库，凭证不回传前端 |
| HTML | DOMPurify + sandbox iframe + CSP | 严格白名单；脚本、外部 CSS 与非 HTTP(S) 资源始终阻止；远程图片按发件人可信度加载 |
| 测试 | Go testing + Bun test + jsdom | 覆盖持久化、协议和不可信 HTML |

## 本次已验证

- `CGO_ENABLED=0 go test ./...` 通过。
- SQLite 关闭后重新打开，账号、正文与草稿恢复成功；列表不携带完整正文。
- 中文 MIME 收发编解码、GB2312/Base64 解析、主题换行注入与非法收件人拒绝。
- 本地真实网络监听器上的 IMAP TLS / STARTTLS 认证、追加邮件、邮件头与正文获取。
- 本地真实网络监听器上的 SMTP TLS / STARTTLS 认证与中文邮件投递。
- 服务器 TLS 握手失败时不发送密码。
- HTML 脚本、远程图片、样式、事件属性和 iframe 清洗；链接仅保留 HTTP(S)。
- `bun run build:web` 类型检查与前端构建通过。
- `bun run build` 生成 macOS arm64 应用与 DMG。首轮构建应用约 15.4 MB，DMG 约 4.8 MB。
- 在 macOS 桌面实际打开应用，通过界面写入本地示例、读取列表、显示隔离的 HTML 邮件，并检查账号表单。

本地协议联调使用仅在测试进程信任的测试证书，生产代码仍使用系统信任链与 TLS 1.2 最低要求，不开放跳过证书验证的选项。

## 尚需验证

没有使用真实邮箱凭证，也没有向外部收件人发送测试邮件。QQ、163、Gmail 的真实收发和系统钥匙串往返，需要用户在应用内添加账号后验证；本地联调不能代替服务商兼容性验收。

尚未验证 Windows / Linux、旧版 WKWebView、完整进程组内存、启动耗时和 8 小时稳定性。0.3.0 的包体为应用约 17.6 MB、DMG 约 6.9 MB，内存指标仍不能下结论。

0.3.0 的 mailto 链路已在本机用系统事件端到端验证：打包后 `Info.plist` 的 `CFBundleURLSchemes` 含 `mailto`，`open -a "My Mail.app" "mailto:…"` 触发 `OnOpenURL`，日志依次出现 `mail.mailto.open` 与 `mail.mailto.emitted`。但「网页里点 mailto 链接自动打开 My Mail」仍要用户先把 My Mail 设为系统默认邮件阅读器；设置页的「测试写信窗口」按钮可绕过这一设置直接验证解析与写信窗口。

0.1.9 的 IMAP IDLE 已在本机真实网络下确认两个账号各有一条稳定长连接、无重连抖动；也观察到一次真实 `EXISTS` 推送（`mail.idle.exists`），9 毫秒内就触发了常规检查。但那次没有新增未读邮件、没有产生通知，所以「新邮件 → 通知」的最后一环仍需用一封真实新邮件验证。

## PRD 需要调整的地方

1. **Outlook 登录范围。** Outlook.com 要求 OAuth2，与 MVP 排除 OAuth2 冲突。建议先不纳入首轮兼容验收，或提前加入 OAuth2 并调整工期。[官方设置](https://support.microsoft.com/en-us/outlook/pop-imap-and-smtp-settings-for-outlook-com)
2. **旧系统兼容性。** Tailwind 4 官方浏览器下限为 Safari 16.4、Chrome 111、Firefox 128；macOS 12+ 的所有环境不能直接承诺。需要明确最低 WebView 版本并做实机验证，或评估 CSS 兼容改造。[官方兼容说明](https://tailwindcss.com/docs/compatibility)
3. **离线定义。** 邮件头已同步不代表正文已缓存；仅缓存成功的正文支持离线阅读。原型已随滚动按需缓存更早的邮件头，后续同步不会清理这些历史页，0.3.0 也补上了每个账号/文件夹的容量上限与淘汰策略（连正文与附件一起清理、保护待同步队列）。仍需在真实大邮箱上验证淘汰后「加载更早邮件」不会把已删除的窗口反复拉回。
4. **同步策略。** 新 UID 增量之外，还要核对其他客户端的标记与删除；0.2.0 已引入持久化待同步操作队列，区分临时错误（保留重放）与永久错误（回滚），但仍需按服务商实测 UIDVALIDITY 变化、并发连接数与 MOVE 回退行为。
5. **草稿优先级。** 防丢草稿已在 PRD 中上调为 P0；0.1.9 实现每键自动保存与重开恢复，0.2.0 改为按账号 + 上下文键多份并存（`reply:<id>` / `forward:<id>` / `new`）。草稿里保存的是附件路径，文件被移动或删除后发送会失败；草稿同步到服务器仍未实现。
6. **已发送副本。** 0.2.0 已做成可配置策略：默认不追加，开启后仅在 SMTP 确认成功时 APPEND，APPEND 失败只提示、绝不重发。仍需逐服务商验证自动保存行为，避免重复副本。
7. **mailto 默认处理器。** 0.3.0 已注册 `mailto` URL scheme 并在 Go 侧解析链接，但 macOS 上必须由用户在系统设置里把 My Mail 选为默认邮件阅读器才会生效；这一环节和冷启动传参需要在真实系统上验收。

## 下一轮顺序（0.3.0 收口后）

0.3.0 已交付 mailto 深链、列表虚拟滚动与缓存容量上限/淘汰；`tests/stage3.test.tsx`、`backend/cache_test.go`、`backend/mailto_test.go` 覆盖了本机可验证的部分。接下来的第一优先级仍是**真实 QQ 或 163 账号的端到端验收**：添加账号与钥匙串、中文编码、发信与抄送/密送、附件收发、回复/转发、通知点击定位、删除/移动/星标/标记未读、一封真实新邮件的 IMAP IDLE 推送延迟，以及把 My Mail 设为默认邮件阅读器后点击 mailto 链接。本地协议监听器和示例账号不能代替服务商兼容性验收（`backend/manage_test.go` 已在本地 IMAP 服务器上验证 STORE / MOVE / UID EXPUNGE，仍不等于服务商兼容）。随后做 Windows / Linux 与旧版 WebView 兼容、完整进程组内存、启动耗时与 8 小时稳定性验收；OAuth2（Outlook / Gmail）、全文索引、草稿同步到服务器与自动更新按发布范围排期。
